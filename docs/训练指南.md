# 训练指南

本文说明怎么从零复现发布的 T10M 对话版 `d10f`，以及怎么换成更小、更快的模型。

## 环境

- Python 3.10+，`pip install -r requirements.txt`。PyTorch 请装 CUDA 版。
- NVIDIA 显卡：12 GB 显存够用（RTX 4070 SUPER 实测）。`--compile` 能快约 2 倍；Windows 上需要 `triton-windows`。
- 内存 32 GB。所有重任务都通过 `t44k.capped` 限制内存（默认 11 GB），超出时报错退出，不会拖死系统。**一次只跑一个大任务，训练时不要开着游戏的大世界。**

## 一键配方

```
python -m t44k.pipeline train d10f --dry-run     # 只列出所有步骤和命令
python -m t44k.pipeline train d10f               # 依次执行；输出已存在的步骤会跳过
python -m t44k.pipeline train d10f --from qa     # 从某一步重新开始
```

| 步骤 | 做什么 | 输入 | 输出 | 耗时 / 成本 |
|---|---|---|---|---|
| topics | 从维基条目名取话题词 | `data/wiki_raw.json` | `data/teacher/topics.txt` | 1 分钟 |
| teacher | DeepSeek API 生成通用中文短句 | 环境变量 `DEEPSEEK_API_KEY` | `data/teacher2/raw.jsonl`（约 215 万句） | 约 10 美元，可断点续跑 |
| vocab | 联合字表：老师语料和 LCCC 字频各占一半 | 老师语料 + LCCC | `data/mixd/vocab.json` | **仓库里已有，会跳过**；想复用发布的权重就别重建 |
| mix | 老师语料拼成 ≤63 字的段落，维基重切 | 老师语料 + 维基 | `data/mix64d` | 几分钟 |
| dialog | 清洗 LCCC，轮次用 `\|` 分隔 | `data/lccc/*.jsonl.gz` | `data/dialog64d`（342 万段） | 几分钟 |
| dedull | 万能回答所在的对话只留 10% | dialog64d | `data/dialog64e`（265 万段） | 1 分钟 |
| judge | 训练浮点评委模型（2580 万参数） | mix64d + dialog64d | `t44k/ta_dialog/ta.pt` | 约 30 分钟 |
| qa | 挖问答：评委打分（PMI），留前 40% | dialog64d + 评委 | `data/qa_lccc`（43 万组 + 1 万组"不知道"） | 几十分钟（显卡） |
| dialog64f | dialog64e + 问答 ×2 | | `data/dialog64f` | 秒级 |
| train | T10M 量化感知训练：16 万步 × 256，70% 权重为零 | mix64d + dialog64f | `t44k/model_d10m_f/q.json` | 约 7.5 小时 |
| model | 打包成模型目录：测解码惩罚、算字频 | | `models/d10f_retrained/` | 1 分钟 |

然后编译、核对、生成行为包：

```
python -m t44k.pipeline build models/d10f_retrained out/mine --check
```

`--check` 会用严格解释器逐条执行全部命令，和整数规范比对每一个中间整数，trunc 和 floor 两种除法语义都要过。T10M 第一次要算矩阵公共子式（CSE），约 3 小时，结果缓存在 `t44k/cse_cache/`。**必须看到两次 `STAGED OFFLINE CHECK PASS` 才能上机**。

## 需要自己下载的数据

脚本不会自动下载。请自己下载，放到对应位置：

| 文件 | 放到 | 来源 |
|---|---|---|
| 中文维基 | `data/wiki_raw.json` | huggingface.co/datasets/0xDing/wikipedia-cn-20230720-filtered（`wikipedia-cn-20230720-filtered.json`） |
| LCCC base | `data/lccc/lccc_base_train.jsonl.gz` 等 3 个文件 | huggingface.co/datasets/silver/lccc |

DeepSeek 的 API 密钥只放在环境变量 `DEEPSEEK_API_KEY` 里，不要写进文件或提交到仓库。

## 换成更小、更快的模型

尺寸在 `t44k/spec.py` 的 `CONFIGS` 里：

| 配置 | 参数 | 每字（实测） | 游戏内存 |
|---|---|---|---|
| `t1m64` | 125 万 | 约 3 s | 约 4 GB |
| `t4m` | 447 万 | 约 5.3 s | 约 7 GB |
| `t7m` | 682 万 | 约 7.9 s（估计） | 约 8 GB |
| `t10m` | 966 万 | 约 11 s | 约 9.3 GB |

把配方里 `train` 一步的 `--config t10m` 换掉即可。小模型训练更快，例如 T4M 8 万步约 1.6 小时。

规模和对话质量的关系（同样的数据、8 万步，对话验证集损失）：

| 模型 | 损失 |
|---|---|
| T4M | 3.640 |
| T7M | 3.560 |
| T10M | 3.492 |

参数越多越好，但每字的时间和内存也同比例上涨。

## 自己的语料

- 文本格式：每行一个样本，最多 63 个字；对话的轮次用 `|` 分隔，例如 `你好|你好呀|在干嘛`。
- 字表：只能用 `vocab.json` 里的 1024 个字，其余的字会变成 `<UNK>`。想换字表，要用 `data/build_joint_vocab.py` 或 `data/prep_mix.py` 重建字表，再从头训练。
- **数据来源要合法**：不要用闭源模型（Claude、GPT、Gemini 等）的输出当语料，它们的服务条款一般禁止这样做。开源权重模型（DeepSeek、Qwen 等）请先确认条款允许蒸馏。

## 训练到上机的完整检查清单

1. 训练日志末尾的整数模型准确率（`int_val_top1`）和浮点准确率相差不大。
2. `pipeline build ... --check`：两次 PASS。
3. `pack --verify`：每个方块都和导出一致（`build` 会自动跑）。
4. 游戏里按"自检"显示 PASS。

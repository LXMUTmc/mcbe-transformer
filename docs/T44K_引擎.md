# T44K 引擎（v0，2026-09-29）

## 状态

**引擎实机验收通过（随机权重）**：24 个提示词、384 次前向，在网易 MCBE 实机里每个生成 token、最终隐藏状态都和 Python 整数规范逐个一致；逐组单步调试时，第一次前向的全部 1,314 个中间整数也一致。每个 token **约 0.6 秒**（每次前向约 12 个 tick）。

用的是**随机三值权重**：先验证引擎算得对，和模型好不好无关。训练出的真模型要等语料（用户提供，或开源模型蒸馏，见 CLAUDE.md），届时只需替换权重再验收一次。

## 规格

2 层，d=32，4 头 × 8，FFN 112（ReLU），词表 320，上下文 16，Pre-RMSNorm（无 affine），INT8 token/位置 embedding，三值 Q/K/V/O/FFN/LM head（60% 为零），独立 LM head，贪心 argmax，**43,520 参数**。

## 代码

| 文件 | 作用 |
|---|---|
| `t44k/spec.py` | 整数规范（唯一真相）：`IntModel`、LUT、校准、随机验证模型 |
| `t44k/compiler.py` | 规范 → 记分板命令，分成三个"tick 组"：G0 = embedding + 第 0 层，G1 = 第 1 层，G2 = 最终归一化 + LM head + argmax + 控制 |
| `t44k/layout.py` | 摆放清单：组链（脉冲链头）+ 控制器；`regate()` 处理条件方块的几何规则 |
| `t44k/check_offline.py` | 命令解释器逐条执行命令文本，比对所有中间整数（M1–M4 离线） |
| `t44k/sim.py` | 逐 tick 世界模拟：三种脉冲触发方式，条件方块按几何规则判断 |
| `t44k/export_plan.py` | 导出 plan.json / programs.json，检查命令文本和寄存器名 |
| `t44k/ingame.py` | 在游戏里通过调试桥执行：摆放、试写寄存器名、初始化、单步或自动验收 |

```
python -m t44k.check_offline 20      # 离线：320 次前向 0 不一致（两种除法语义）
python -m t44k.sim 6                  # 世界模拟：当场 / 下一 tick / 重复触发 三种都 PASS
python -m t44k.export_plan <ASCII 目录> 16384 0
```

## 关键设计

- **三个 tick 组**：每组一条链，由控制器用红石块触发脉冲链头，组尾自己断电、推进组号并重新上膛（这些命令带守卫）。控制器先把"上膛"读进局部标志 `go` 再清零，避免同一 tick 内连续触发时锁死。
- **SSA 寄存器**：每层、每个阶段写自己的名字，所以重复执行不会改变结果；只有控制部分（pos/cur/out/run）不是幂等的，都用 `grp == 2` 守卫。
- **门 + 条件块分派**：embedding（317 个 token 各一段）、位置、KV 写入都是"一条门命令 + 一段条件连锁块"，每个 token 只执行被选中的那一段（embedding 实际只跑 33 条，而不是 1 万条）。
- **每 token 执行约 2.47 万条**命令（静态约 4.15 万块，其余是被跳过的条件块）。

## 实机踩到的坑（都已修复并写进工具）

1. **条件连锁块按"几何上身后的方块"判断，不是按链上的前一个**。蛇形布局每次转弯有两个格子不满足这一点，导致别的 token 的 embedding 行被误执行。修复：`regate()` 在转弯格放当前段"门"的副本（不带条件）；模拟器改成按几何规则判断，关掉修复时能复现这个错误。
2. **敏感词过滤作用在寄存器名上**：含某些特定数字组合的下标、所有 `…j8`、`bl` 被静默吞掉。修复：下标用字母分隔（`K0p7d31`），槽位字母改成 `t`，`bl` 改成 `blg`；导出时检查名字，上机前在游戏里把 3,314 个名字全部试写一遍。
3. 脉冲链头是在**之后的某个 tick** 执行，不是在 `setblock` 通电的当下。
4. 调试桥：`SetCommand` 必须传字节串，JSON 读出的 unicode 要 `.encode('utf-8')`；重新摆放前要先清空整个区域。

## 提速：单链布局（v0.1，2026-09-29）

- 三个组合并成**一条链**（41,556 个方块，在单链上限 65,535 以内），用需要红石的循环链头：开始时放红石块，每 tick 跑一次完整前向，`run` 变 0 时链尾拆掉红石块。
- 网易的循环链头断电后会多跑 1–2 次，用 v0.1.2 的做法处理：链的第一条命令先把 `live = run` 锁存下来，控制逻辑只在 `live==1` 时执行；计算部分是 SSA，多跑不影响结果；结束时给最终状态拍快照（`cxf1x*`、`cbt`、`cblg`），验收比对快照。
- 世界模拟：循环链头在断电后多跑 0/1/2 tick 三种情况都 PASS；另一种"脉冲链头自己重新触发"的布局（`single_impulse`）也 PASS，留作备选。
- **实机：24 个提示词、384 次前向全部逐整数一致；434 个 tick、53.3 秒，每个 token 约 0.14 秒**（原来 0.6 秒）。每 tick 约 123 ms，已经是纯计算瓶颈（约 2.5 万条有效命令，每条约 5 µs）。
- 导出：`python -m t44k.export_plan <目录> 16384 0 single`（默认就是 single；`groups` 是原来的三组布局）。

## 第一个训练模型（2026-09-30）

- **词表 320 → 512**（用户同意）：320 个字时语料只有约 30% 的句子能用。参数 55,808，单链约 5.06 万块，每 token 约 2.74 万条有效命令。
- **语料**：DeepSeek 官方 API（`deepseek-flash`，其服务协议 4.2(3) 允许用于训练其他模型）。第一轮不限字，约 1.7 万句；第二轮把 `data/charset.txt`（504 个字加 4 个标点，按第一轮字频选出）写进提示词限定用字，可用率 74%。合并清洗后 5.58 万句，筛掉词表外的句子、问答句限制到 10% 后，**可用 32,401 句**（train 30,781 / val 1,620），平均 7.1 个字。每条语料都记录了来源。
- **训练**：`t44k/train.py`，在规范的整数单位里做量化感知训练（三值 STE、INT8 embedding、ATTDIV/MO/M2 每层可学习，R=65536）。RTX 4070 SUPER，4 万步 batch 512，约 15 分钟。验证集下一个字准确率 31.4%（浮点）/ 31.0%（整数）。
- **实机**：24 个真实提示词（验证句的前两个字）在游戏里**逐 token、逐状态全部和整数规范一致**，每句约 1–1.7 秒。示例：石镐→挖石头、熟牛→肉能回血、我挖→到红石矿。、洞里→见僵尸。、白天→黑前回家、给村→民换东西、换把→石头砍树、骷髅→射箭。
- 限制问答句之前的版本太爱套"能做啥？能。"，限制后明显少了。

## M6：独立世界（2026-09-30）

- `python -m t44k.m6 <目录>` 导出 m6.json（远处 52,764 块 + 513 个按键）；`python -m t44k.sim_m6` 在三种链头时序下模拟 PASS。
- 远处（x=16384 常加载区）：核心单链；常开轮询器（把 `in` 追加到提示词 t1..t15，自检结束时比对 16 个输出 + 34 个快照 = 50 个整数）；初始化脉冲链（建记分项、常量、KV，最后一条拆掉自己的电源）。
- 玩家身边：键盘墙，每个字一个按钮 + 命令方块 + 告示牌；底行是 清空 / 退格 / 生成 / 自检 / 初始化。按钮只写记分板、放红石块，不含计算。
- 生成和自检先把 `run==0` 锁存进 `ok` 再动手（`start` 本身会把 run 设成 1）。
- 实机：初始化 → 石镐 → 生成 = 挖石头<EOS>（和规范一致）；自检 骷髅→射箭<EOS>，err=0 PASS；故意改一个快照整数 → err=1 FAIL。
- 告示牌文字另有过滤：`泽`、`近`、`jin` 写不进告示牌（tellraw 聊天输出正常），改用 `ze`、`j-i-n`。
- 第一版键盘按钮直接挂在命令方块上，会串线（相邻键一起触发）；改为 按钮 → 石头 → 命令方块（`m6.check_keyboard`：旧 508/508 串线，新 0）。
- **用户实测：新键盘不串线；关掉全部组件后，手动输入、生成、自检 PASS。M6 完成。**

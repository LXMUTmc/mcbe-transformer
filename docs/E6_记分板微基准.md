# E6 记分板微基准（2026-10-02）

## 目的

GPT 调研 v6 建议：在单 tick 很长的 T4M 世界之外，单独测记分板命令的单价，找可以调的地方。

## 方法

- 新建空白世界（只挂 DebugBridge），测试区在 x=8192 的常加载区，远离玩家。
- 一条 **10 万个命令方块的单链**，蛇形 192×63，链头是需要红石的循环命令方块；另放一个常开的循环块，每 tick 执行 `add tk kc 1` 计数。
- 每种写法放在同一组位置上（覆盖前一种），链长相同，所以几何结构和空转条件都一样。
- 每组：通电 → 预热 4 秒 → 计 15 秒内的 tick 数 → 断电。结果记为"毫秒 / tick"，除以 10 万就是每条命令的耗时。
- 数值不会越界：命令成对出现（`T += S`，再 `T -= S`）。
- 脚本：scratchpad 下的 `bench_ig.py`（调试桥里执行，Python 2）。

## 结果

| 写法 | ms / tick（10 万条） | 每条约 |
|---|---|---|
| 链存在但不通电（空转） | 50（满速 20 TPS） | — |
| 基准 `operation += / -=`，256 名字 × 128 记分项，交错写（开头 / 结尾） | 488.5 / 530.9 | 4.9–5.3 µs |
| 假玩家名 32 × 记分项 1024 | 467.2 | 4.7 µs |
| 假玩家名 128 × 256 | 492.5 | 4.9 µs |
| 假玩家名 1024 × 32 | 514.9 | 5.1 µs |
| 假玩家名 4096 × 8 | 506.7 | 5.1 µs |
| 同一名字集中写（256 条一组） | 500.6 | 5.0 µs |
| `add T 1` | 477.0 | 4.8 µs |
| `operation T += c1 kc`（常量记分项） | 493.5 | 4.9 µs |
| `set T 5`（值不变） | 442.6 | 4.4 µs |
| `=` / `-=` / `*=` / `/=` / `%=` / `>` / `<` | 520 / 464 / 498 / 520 / 513 / 510 / 529 | 4.6–5.3 µs |
| `execute if score T matches ..2147483647 run` 运算（条件成立） | **755.1** | **7.6 µs** |
| `execute if score T matches ..-2000000000 run` 运算（条件不成立） | **454.7** | **4.5 µs** |
| 一个失败的门控后面接 99,998 个条件块（全部跳过） | 143.4 | 1.4 µs |
| 条件块执行（无效：蛇形拐弯处条件块判断错位，后面实际都被跳过了） | 142.8 | — |
| 长名字 `qqqqqqqqqqqqq<n>`（无效：32,768 个名字全部被网易过滤） | 425.9 | — |

前后两次基准相差约 9%（488 → 531），所以 10% 以内的差别都算噪声；每组只计到 30–36 个 tick，计数本身也有约 3% 的误差。

## 结论

1. **记分板细调没有可挖的空间**：名字数 32–4096、名字和记分项的比例、写入顺序、`add` 还是 `operation`、运算种类，差别都在噪声以内。现在的 256 名字映射不用改。（"不同名字超过约 5000–20000 后断崖"那条规则仍然有效，本次最多只测到 4096 个名字。）
2. **`execute if` 很贵**：条件成立时 `execute if … run X` 比单独执行 X 贵约 50%（+2.6 µs）；条件不成立时也要约 4.5 µs，和执行一条运算差不多。查找表这类"一串区间判断"的写法，每一条都按这个价钱算。
3. **被跳过的条件块约 1.4 µs**，比失败的 `execute if` 便宜约 3 倍。
4. **新屏蔽词**：假玩家名里出现 `qq` 会被吞（已加入 `netease_lint.NAME_RISKY`）。
5. 用这些单价拆 T4M 每字（位置约 20）：普通运算 99 万条约 5.0 s，注意力里被执行的条件块约 1.0 s，被跳过的块约 57 万个约 0.8 s，`execute if … run` 7.4 万条约 0.35 s，合计约 7.2 s（实测 5.7–6.2 s，量级相符）。**大头仍然是矩阵乘本身**；其次是被跳过的块（约 13%），softmax 查找表约 5%。

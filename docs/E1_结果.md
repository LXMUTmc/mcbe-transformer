# E1 结果：实体选择器 SIMD vs 拓扑编译

2026-09-29，E1 v1.1.1，网易 MCBE 客户端，i5-13400F。由调试桥（mod-debug-bridge）在游戏进程里自动排队执行，用 `time.time()` 按真实时钟计时（每项 N=100 tick，每 tick 耗时 = (跑完时刻 − 开始时刻) / 99）。**27 项全部 PASS**：每项都逐个核对了 768 个输出整数，SIMD 各项的实体数也都是 768。

## 结论

**实体选择器 SIMD 不值得作为主路线。** 在实用的稀疏度下（5–25% 非零），它比拓扑编译慢 1.3–4 倍；即使非零率达到 50%，也只快 12%。理论上限约 1.9 倍（稠密到极限时），而且世界里实体越多，它越慢。按研究文档的判据（R < 1 就放弃），0.1B 路线走**结构分页 + 拓扑编译**。

## 核心数据

| 非零率 | 非零权重 | 拓扑耗时 | SIMD 耗时 | SIMD 模型预测 | R = 拓扑 ÷ SIMD |
|---|---|---|---|---|---|
| 5% | 9,830 | 43.7 ms（实测） | 179.7 ms | 179.7 | **0.24** |
| 10% | 19,661 | 83.9 ms（实测） | 201.7 ms | 201.7 | **0.42** |
| 25% | 49,152 | 209.6 ms（外推） | 271.0 ms | 267.9 | **0.77** |
| 50% | 98,304 | 419.2 ms（外推） | 375.4 ms | 378.2 | **1.12** |

耗时都是一次 768×256 矩阵乘本身的时间：拓扑减去 T0（84.7 ms），SIMD 减去带实体池的 T0（111.1 ms）。拓扑 25%/50% 没有实测（为了每 tick ≤ 4 万条命令），按 4.26 µs/权重线性外推。

## 成本模型（实测拟合）

| 原语 | 成本 |
|---|---|
| 拓扑：一条 `scoreboard players operation … += / -=`（一个非零权重） | **4.26 µs**（每秒约 23.5 万个权重） |
| 选择器命令的固定开销（768 个实体在场时） | **0.31 ms**，相当于约 70 条普通命令 |
| 选择器每多命中 1 个实体 | **2.24 µs** |
| 选择器固定开销随世界实体总数上涨 | 每多 1 个实体约 +0.27 µs/条（线性，说明在扫描全部实体） |
| 盔甲架光是存在的开销 | **0.034 ms / 个 / tick**（768 个 ≈ 26 ms/tick） |
| 按标签回读 1 个实体 `@e[tag=iK]` | 0.25 ms/条 |
| 按坐标回读 1 个实体 `@e[x,y,z,dx=0]` | 0.073 ms/条（也随实体总数上涨） |
| 选择器加区域限制 `x/y/z/dx/dy/dz` | **更慢**（S10：202 → 276 ms） |

SIMD 要追平拓扑，每条选择器平均要命中约 150 个实体，也就是非零率 40% 左右。而模型要做到 80–90% 为零，正好落在 SIMD 最吃亏的区间。

## 对后续设计的影响

1. 矩阵乘继续用拓扑编译（一个非零权重一条命令），约 4.3 µs/权重。按每 tick ≤ 4 万条算，每 tick 最多约 170 ms、约 4 万个非零权重。
2. 0.1B、10% 非零时有 1000 万个非零权重，约 43 秒/token（纯线性层）。瓶颈在存储：1000 万个命令方块，需要结构分页。**下一个实验是 E2 结构换页。**
3. 不要在运行时世界里放大量实体：每个盔甲架每 tick 固定消耗约 0.034 ms，还会拖慢所有选择器。
4. 需要按位置取数据时，坐标选择器比标签选择器便宜约 3.4 倍，但两者都随实体总数变慢。

# E2 结果：`/structure load` 运行时换页

2026-09-29，网易 MCBE 客户端，i5-13400F。整个实验由我通过调试桥在游戏里完成：用 ModSDK API 摆放页面（`SetBlockNew` + `SetCommandBlock`），用 `/structure save … disk` 存进**世界存档**，由**纯命令方块控制器**换页，按真实时钟计时。代码见 `e2_ingame.py`。

## 设计

- **页面**：一段拓扑编译的三值矩阵乘（约 10% 非零，输入 x0..x255），每行第一条命令用 `=` 起头（SSA）。页面重复执行结果不变，所以不需要"只执行一次"的守卫。页尾依次是本页校验和 `cs<s>_<k>` 和完成标记 `done = k`。
- **执行区**：每种页面尺寸一个固定区域，链头是自动运行的循环命令方块（不需要红石），加载进来就开始执行。
- **控制器**：约 120 个纯命令方块，不调用函数。看到 `done == pg` 就 `structure load` 下一页，覆盖同一个执行区。结束时逐页核对校验和、打印 PASS/FAIL，并拆掉执行区的链头让它停下。
- **页面尺寸**：1K / 4K / 16K / 30K 条命令，每种 2–4 个不同页面，循环加载。

没有卡住、丢页或算错。

## 速度

计时用了 1.2 万条填充链保证每 tick 都超过 50 ms（F0 = 62.1 ms/tick）。"常驻"是指一页加载一次后每 tick 都执行；"换页"是控制器不停换页。

| 页面 | 常驻 ms/tick | 执行一页 | 换页 tick 数 / 执行次数 | **加载一页** | **每个命令方块的加载成本** |
|---|---|---|---|---|---|
| 1K | 67.5 | 5.5 ms | 200 / 400 | 113 ms | **113 µs** |
| 4K | 90.0 | 27.9 ms | 116 / 186 | 423 ms | **106 µs** |
| 16K | 158.8 | 96.7 ms | 46 / 75 | 1.77 s | **111 µs** |
| 30K | 239.2 | 177 ms | 32 / 54 | 3.53 s | **118 µs** |

加载一页 =（换页轮的总墙钟时间 − tick 数 × F0 − 执行次数 × 执行一页的时间）÷ 换页次数。

- **加载成本约 110 µs/个命令方块，和页面大小成线性关系。** 1K 和 4K 页占的区域一样大（64×1×64），成本却差 4 倍，说明成本在命令方块本身，和区域里有多少格空气无关。
- **加载一条命令的成本是执行它的约 20 倍**（执行约 5–6 µs/条）。
- 一次换页平均 1.0–1.16 个 tick。页面加载后当 tick 就执行一次，之后每 tick 再执行，直到被换掉，所以平均每次换页执行 1.5–2 次。因为页面是 SSA 设计，多执行几次不影响结果。

## 对 0.1B 路线的影响

每个 token 要把所有非零权重都执行一遍。如果权重全部靠换页进来，每个权重的成本约 110 + 5 = 115 µs：

| 每 token 非零权重 | 全部换页 | 全部常驻（只算执行） |
|---|---|---|
| 100 万（约 1000 万参数，90% 为零） | 约 2 分钟 | 约 5 秒 |
| 1000 万（约 0.1B，90% 为零） | 约 19 分钟 | 约 50 秒 |

- 换页能用，而且可靠，但代价约 20 倍。**优先常驻，换页兜底**：能常驻的层尽量常驻，其余再换页。
- 预填充（prompt 里的多个 token）可以在同一次加载里连续处理多个位置，把加载成本分摊掉；逐字生成时分摊不了。
- 下一个要搞清楚的是常驻的上限：几百万到上千万个命令方块同时放在常加载区块里，空闲时每 tick 要多少开销、内存和存档有多大、`tickingarea` 能加载多少。这决定了常驻和换页怎么搭配。

## 移除全部附加包：PASS（2026-09-29）

- 第一张实验世界（同时装着 E1 和 E2）退出后再也打不开，进程在加载世界时直接消失，挂不挂附加包都一样。于是在一张新的平坦世界里只挂 DebugBridge 重做了 E2，12 页的校验和与之前完全一致。
- 运行中先移除常加载区、再重新加入，让约 6.5 万个方块的密集区块从存档重新加载，没有崩溃。
- 退出前移除了常加载区，然后把 DebugBridge 也从世界上移除，**零附加包**重新进图，能正常进入。
- 用纯命令按钮加载常加载区，控制器从世界存档里加载 `e2w_4_*`，**30K 页连续换页 40 次：PASS**。
- 结论：页面存在世界存档里，由纯命令方块控制器换页，完全不依赖附加包，符合"原版运行时"的约束。

## 还没弄清的

- 第一张世界为什么打不开。它比新世界多了 E1 的遗留：约 5 万个命令方块（不在常加载区里），`e1a` 记分项里还留着约 1268 个已删除盔甲架的分数，还有 E1 的实体标签等。
- 常加载区**在启动时就已经存在**的情况下，世界能不能正常打开（这次为了稳妥，退出前移除了常加载区）。最终的运行世界需要计算区在启动时就处于常加载状态，下次重进时要验证。

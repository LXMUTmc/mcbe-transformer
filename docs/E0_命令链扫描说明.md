# 实验零（E0）：命令链长度扫描

**为什么先做这个**：E1 一启动（每 tick 8 万多条命令），游戏里所有命令都停止响应，包括聊天栏手敲的 `/tellraw`，但实体、刷怪蛋、挖方块都正常。v0.1.2 每 tick 只有约 7 千条命令，一直正常。E0 要找出命令开始"排不上队"的那条线：它和单条链的长度有关，还是和每 tick 命令总数有关。

| 按钮 | 内容 |
|---|---|
| L1K / L2K / L5K / L10K / L20K / L40K | 1 条链，1 千到 4 万条 `+=` 命令，跑 N tick |
| 8x5K | 同样 4 万条命令，拆成 8 条各 5 千条的链一起跑 |

每条链每 tick 都会检查自己是否跑完了全程，结束时报告"完整执行了几个 tick"。

## 准备

**新建一张平坦世界**（旧图里 E1 的命令还在排队，别再用了），开启作弊，挂上 `E0_命令链扫描_MCStudio组件_v1_0_0.zip`。

```
/gamerule commandblockoutput false
/tickingarea add 4096 90 0 4159 190 63 e0
```
等 3 秒：
```
/function e0/place
/tp @s 10 100 -4
```
面朝南会看到一排按钮，先按「初始化」（默认 N=20）。

## 测试

**从短到长**依次按：L1K → L2K → L5K → L10K → L20K → L40K → 8x5K。

每个测试：
1. 按下按钮的同时开始计时，看到"完成 … 请停表"就停表，记下秒数和 PASS/FAIL。
2. 测试进行中，在聊天栏敲一次 `/say ping`，记下多久才显示出来（立刻 / 几秒 / 一直不出来）。

**哪一项超过 30 秒还没完成，就停下，后面更长的都不要再测**，直接退出世界（服务端没卡死，可以正常保存退出）。把那一项和之前各项的结果发我。

N=20 时，20 TPS 满速对应 1 秒。L1K、L2K 应该就在 1 秒左右。

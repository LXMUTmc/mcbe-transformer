## 二、硬约束（不可违反）

- **运行时只用原版命令系统**：命令方块、记分板、方块、原版命令。行为包 `.mcfunction`、Script API、网易 ModSDK 都**不算**原版运行时，只能在开发期用来搭世界或调试；世界搭好后必须能移除所有附加包继续运行。
- token 编码、网络计算、选下一个字、连续生成都在游戏里完成，**不许外部算好、游戏里查表**。
- 整数运行时必须和 Python 整数规范**逐整数一致**，"99% 一致"算失败。
- 训练语料**不能用 Claude、GPT、Gemini 等闭源模型的输出**。只能用：用户自己写或收集的文本、许可明确的公开数据集、开源权重 teacher（本机或第三方 / 官方 API 均可，确认服务条款允许蒸馏）。每条语料记录来源。

## 三、路线选择：为什么这么做

所有结论都来自实机测量（i5-13400F，调试桥真实时钟计时）。

### 3.1 计算方式：拓扑编译（一条命令 = 一个非零权重）

权重是三值（−1 / 0 / +1），直接编译进命令文本：`y += x_i`、`y -= x_i`，零权重不生成命令。每个非零权重约 **4.3–5.6 µs**（E1、T44K）。

| 候选方案 | 实测 | 结论 |
|---|---|---|
| 实体选择器 SIMD（一条命令作用于一批实体） | 每条固定 0.31 ms，每命中一个实体 2.24 µs，还随世界实体数线性变慢 | **淘汰**（E1） |
| NX 分叉（共轭二分 / N 叉树，用户提供的技巧） | 可用，但每个叶子 3–5 µs，和常驻命令一样；所有叶子执行同一段文本，写不到不同寄存器 | **不能加速计算**，只适合扫描方块 ROM（E3） |
| 方块 ROM + NX 矩阵乘 | 结果正确，但每个非零权重 63 µs，是拓扑的约 15 倍 | 不作主线（E3） |
| **拓扑编译，常驻命令方块** | 约 4.5 µs/条；空闲约 0.1–0.22 µs/块/tick；内存约 2.5 KB/块 | **主线** |

### 3.2 存储：常驻优先，换页兜底

| 方式 | 成本 | 来源 |
|---|---|---|
| 常驻命令方块 | 执行 4.5 µs/条；空转 0.1–0.24 µs/块/tick；**内存 2.5 KB/块** | E4 |
| `/structure load` 换页 | 约 52–110 µs/命令方块（执行成本的约 20 倍），1678 次换页全部正确 | E2、E3 |
| 普通方块加载 | 6.5 µs/块 | E3 |

- **内存是第一道墙**：普通电脑大约常驻 200–300 万个命令方块，按 60% 为零算约 5–7M 参数。
- 计算上限（每参数约 0.4 条命令 × 约 4.5 µs）：1M 参数约 2 秒/字，10M 约 20 秒，0.1B 约 3 分钟，1B 约 30 分钟（理想值；实测见 3.4）。
- 超过常驻上限后要换页或用普通方块 ROM。候选方案（未测，E5）：普通方块存权重，`/clone` 搬进固定读取窗口，读取程序用 `execute if block` 决定加减。

### 3.3 数值：整数规范 + 三值权重

- 记分板只有 32 位整数，所以网络本身就定义成整数运算（`t44k/spec.py` 是唯一真相），PyTorch 训练时在同样的整数单位里做量化感知训练（STE 取整）。
- 三值权重让每个权重对应一条最便宜的命令；INT8 embedding；RMSNorm 和 softmax 的 exp 用查找表。
- 除法统一写成 `add K·D + D/2 → /= D → remove K`，保证被除数非负、四舍五入，和平台对负数的取整方式无关。

### 3.4 执行节奏：一个 token 在一个 tick 里算完

- 常驻方块每 tick 都要付空转成本（T1M 约 200 ms/tick），所以一个 token 用的 tick 越少越好。
- 分阶段版（每阶段一条链，链尾接力）实测：**接力要 2 个 tick**，15 个阶段 = 30 个 tick，光空转就约 6 秒/字。
- **`gamerule maxcommandchainlength` 可以调到 1,000,000**（实测一条 10 万块的链完整执行），所以现在把整次前向放进**一条链、一个 tick**。T1M 单链：每字 1 tick、12.8 秒，此时游戏里 SrvTime 显示约 15000（毫秒）。
- 未解决：长链里每条命令实际约 9–20 µs，比小基准（4–6 µs）慢 2–4 倍，原因还没查明（见 `docs/大规模路线.md`）。

### 3.5 语料

- T44K：DeepSeek 官方 API（`deepseek-flash`，其开放平台服务协议 4.2(3) 允许把输出用于训练其他模型），MC 主题短句，3.24 万句。
- T1M：中文维基百科（`0xDing/wikipedia-cn-20230720-filtered`，CC BY-SA 3.0，人写文本），142 万条、2770 万字；1024 个常用字以外的字记为 `<UNK>`，只作为上下文，不当训练目标，也不会被生成。

## 四、引擎原理

### 4.1 模型（decoder-only Transformer）

每个 token 的计算：`x = E[tok] + P[pos]` → 每层（Pre-RMSNorm → Q/K/V 三值投影 → 写 KV 缓存 → 因果注意力 → O 投影残差 → RMSNorm → FFN 上投影 + ReLU → 下投影残差）→ 最终 RMSNorm → 三值 LM head → argmax（严格 `>`，并列时 id 小的胜）。

| 常量 | 值 | 作用 |
|---|---|---|
| S | 64 | 残差 / 归一化激活的比例尺 |
| PS / QS | 4 / 4 | RMSNorm 平方前、q·k 前的预缩放 |
| INVR | 4096 | RMSNorm 倒数的定点精度（查找表，48 档几何分箱） |
| U | 0.25 nat | 注意力分数单位；exp 查找表，满权 256 |
| KATT | 65536 | 注意力可变分母的偏移乘数 |
| ATTDIV / MO / M2 | 每层可学习，导出时取整 | q·k 缩放、O 投影与 FFN 下投影的输出缩放（R=65536） |

尺寸由 `spec.configure("t44k" | "t1m")` 选择（`spec.CONFIGS`）。

### 4.2 编译：规范 → 记分板命令（`t44k/compiler.py`）

- **三值行**：每个输出一行，第一个非零项用 `=`，之后 `+=` / `-=`。
- **SSA 寄存器**：每层、每个阶段写自己的名字（`q3x17`、`K2p5d100`…），所以任何一段被重复执行，结果都不变（网易的链头会多跑，见六）。
- **门 + 条件块分派**：embedding（每个 token 一段）、位置、KV 缓存写入都是"一条门命令 `execute if score cur matches t` + 一串条件连锁块"，只有被选中的那段真正执行。
- **因果跳过**（分阶段编译）：注意力只算 j ≤ pos 的位置，平均省一半注意力命令。
- **自成一体的单元**（`staged=True`）：编译器在"没有寄存器跨单元修改"的位置插入切分标记，便于把前向切成多条链；embedding 拆成 `ee = E[cur]`、`pp = P[pos]`、`xe = ee + pp`；掩码、ReLU 放进写同一寄存器的单元里；LM head 分块求局部 argmax，最后按 token 顺序合并。
- **控制段**（唯一不是 SSA 的部分）：把下一个字写回、输出已生成的字、遇到 EOS 或写满上下文就停；由锁存标志守卫（单链用 `live`，分阶段用 `stg`），停机时把最终状态快照到 `c*` 寄存器供自检比对。

### 4.3 布局（`t44k/layout.py`）

- 命令方块按蛇形排列（默认每层 64 × 63，T1M 单链用 192 宽），全部放在**远离玩家的常加载区**（x=16384、32768 …）。
- 单链：链头是"需要红石"的循环命令方块，开始时在旁边放红石块，每 tick 跑一次完整前向；`run` 变 0 时链尾拆掉红石块。链首第一条命令 `live = run` 锁存，控制段只在 `live==1` 时执行，吸收网易链头断电后多跑的 1–2 tick。
- `regate()`：条件块判断的是**几何上身后**的方块，蛇形转弯处有两个格子不满足，所以在那里放一份当前段门命令的无条件副本。
- 分阶段（`build_plan_staged`）：每阶段一条脉冲链，链尾先锁存 `stg == k` 再推进 `stg`、最后才给下一阶段通电，重复触发的链不会接力出第二条流水线。

### 4.4 M6 独立世界（`t44k/m6.py`）

- 远处：核心单链；**常开轮询器**（把键盘输入的字追加到提示词缓冲 t1..t15；自检结束时比对 16 个输出 + 34 个快照 = 50 个整数，打印 PASS/FAIL）；**初始化脉冲链**（建记分项、常量、KV 缓存、控制寄存器，最后拆掉自己的电源）。
- 玩家身边：键盘墙（508 个字键 + 清空 / 退格 / 生成 / 自检 / 初始化）。每个键是 按钮 → 石头 → 脉冲命令方块 → 连锁块，按钮只写记分板或放红石块，不做计算。
- "生成"和"自检"先把 `run==0` 锁存进 `ok` 再动手（开始程序本身会把 run 设成 1）。

## 五、验证体系

每一层都要逐整数通过，才进入下一层。

| 层级 | 工具 | 内容 |
|---|---|---|
| 整数规范 | `spec.IntModel` | 唯一真相；带范围守卫（\|值\| ≥ 2²⁸ 报错） |
| 命令文本 | `t44k/check_offline.py`、`t44k/check_staged.py` | 严格解释器（`vm.py`）逐条执行真实命令文本，比对每个中间整数；截断 / 向下取整两种除法语义都要过 |
| 世界时序 | `t44k/sim.py`、`t44k/sim_m6.py` | 逐 tick 模拟：条件块几何规则、脉冲链头当场 / 下一 tick / 重复触发、循环链头断电后多跑 0/1/2 tick |
| 名字 | `netease_lint.check_names` + 游戏内试写 | 敏感词过滤会吞掉某些记分板名字，上机前把全部名字在游戏里试写一遍 |
| 实机 | `t44k/ingame.py`、`t44k/ingame_staged.py` | 通过调试桥搭建，跑提示词，逐 token 比对输出和最终状态快照 |
| 独立运行 | M6 自检按钮 | 关掉全部组件后在游戏里自检（50 个整数），另做过负对照（故意改一个整数 → FAIL） |

常用命令（在项目目录，用 `.venv` 的 Python 3.12）：

```
.\.venv\Scripts\python.exe -m t44k.check_offline 20 --trained      # T44K 训练模型，命令级比对
.\.venv\Scripts\python.exe -m t44k.sim 6                           # T44K 世界模拟
.\.venv\Scripts\python.exe -m t44k.sim_m6                          # M6 世界模拟（键盘→生成→自检）
.\.venv\Scripts\python.exe -m t44k.check_staged t1m 1              # T1M 分阶段编译，命令级比对（约 3 分钟）
.\.venv\Scripts\python.exe -m t44k.sim 3 staged t44k 8000          # 分阶段接力的世界模拟
```

## 六、网易平台的坑（全部实测）

| 现象 | 规则 / 对策 |
|---|---|
| 敏感词过滤会**静默吞掉**命令（不报错） | 命令文本、记分项名、假玩家名都受影响：`sb`、`…j8`、`bl`，以及含某些特定数字组合的名字等。下标用字母分隔（如 `K0p7d31`）；构建时跑 `netease_lint`，上机前逐个试写名字 |
| 告示牌文字另有过滤 | `泽`、`近`、`jin` 写不进告示牌（tellraw 正常），改写 `ze`、`j-i-n` |
| 条件连锁块 | 判断的是**几何上身后**那个方块上次是否成功，不是链上的前一个（`regate()`） |
| 脉冲链头 | `setblock` 放红石块后要**之后的 tick** 才执行（链尾接力实测 2 tick，调试桥放是 2–4 tick） |
| 循环链头（需要红石） | 断电后还会多跑 1–2 tick → `live` 锁存 + SSA + 停机快照 |
| 按钮挂在命令方块上 | 会强充能该方块，连带触发相邻命令方块（串线）→ 按钮挂在石头上，命令方块放在石头后面 |
| 渲染距离内有大量命令方块 | 非常卡 → 所有大结构放到远处的常加载区，玩家身边只放键盘 |
| 调试桥 | 游戏窗口不能在后台或打开暂停菜单（tick 停了会连接超时）；`SetCommand` 要传 UTF-8 字节串；新常加载区要等区块加载后再摆方块 |
| SrvTime | 服务端一个 tick 的耗时（毫秒）；T1M 单链时约 15000。帧率不受影响，但这段时间世界是停住的 |
| 链长上限 | `gamerule maxcommandchainlength` 默认 65535，可调到 1,000,000 |

## 八、部署

### 8.0 环境

- 电脑：Windows（开发机系统 `python` 是 2.7，所以一律用项目 `.venv` 里的 Python 3.12，含 numpy、PyTorch 2.11+cu128）。
- 调试桥 mod-debug-bridge（开发期用，见 `HANDOFF.md`「调试桥」一节）：游戏里挂 DebugBridge 组件，Claude Code 通过 MCP 在游戏里执行 Python 2 代码。
- 路径含中文时，导出目录要用纯 ASCII 路径（游戏内 Python 2 读文件用）。
- **资源**：T1M 世界游戏进程约 4–5 GB。游戏开着大世界时不要同时跑训练。

### 8.1 训练一个模型

```
# T44K（DeepSeek 语料）
.\.venv\Scripts\python.exe data\gen_corpus.py ...          # 用户本机跑；密钥只放环境变量 DEEPSEEK_API_KEY
.\.venv\Scripts\python.exe data\build_vocab.py data\corpus_raw.jsonl data\corpus_pass2.jsonl data\corpus_pass2b.jsonl --charset data\charset.txt --qa-frac 0.1
.\.venv\Scripts\python.exe -m t44k.train --steps 40000 --batch 512           # → t44k/model/q.json

# T1M（中文维基）
curl.exe -L -o data\wiki_raw.json https://huggingface.co/datasets/0xDing/wikipedia-cn-20230720-filtered/resolve/main/wikipedia-cn-20230720-filtered.json
.\.venv\Scripts\python.exe data\prep_wiki.py data\wiki_raw.json --vocab 1024 --out data\wiki
.\.venv\Scripts\python.exe -m t44k.train --config t1m --data data\wiki --steps N --batch 256   # → t44k/model_t1m/q.json
```

训练结束会自动校准 RMSNorm 查找表、测整数模型准确率、打印样例。换了模型后要重新跑五里的命令级比对（T1M：`python -m t44k.check_staged t1m 2 --trained`）。

**训练提速（实测，RTX 4070 SUPER，T1M，batch 512）**：原样 47 ms/步；`--tf32` 48 ms/步（无效，不用）；`--compile` 约 22 ms/步（快约 2.1 倍，开头编译约 1 分钟，验证损失不变）。`--compile` 需要 `triton-windows<3.7`（对应 torch 2.11，已装在 `.venv`）。训练数据以 int16 数组常驻显存；`--bench` 只跑训练步不导出，用于测速。

**T1M 第一次训练（2026-09-30）**：8 万步 × 512，约 63 分钟（未用 compile），验证损失 4.06，下一个字准确率浮点 27.4% / 整数 27.7%。样例：是建→筑物的一个建筑，包括一个小型的建筑……；这本→书的记载，这些文字是一种说法……。贪心解码下容易绕圈重复。模型在 `t44k/model_t1m/q.json`（哈希 00445d24ab337382）。实机导出：`python -m t44k.export_staged <目录> t1m 32768 4 single --trained`。

### 8.2 部署 M6 独立世界（T44K）

1. 导出：`python -m t44k.m6 <ASCII 目录>` → `m6.json`（远处方块、键盘、初始化电源位置、自检期望值）；`python -m t44k.sim_m6` 必须 PASS。
2. 新建超平坦世界，挂 DebugBridge；`/gamerule commandblockoutput false`；加常加载区覆盖 x=16384 起 64×64。
3. 通过调试桥摆放 `m6.json` 的 `blocks`（格式和 `t44k/ingame.py` 的 `place_all` 相同：位置、类型、朝向、条件、是否自动、命令）；先在游戏里试写全部名字。
4. 键盘墙：在玩家附近选原点，用 `t44k/m6_keyboard_ingame.py` 的 `clear_wall()`、`place_wall()`；玩家站在墙北侧、面朝南。
5. 按「初始化」一次 → 按「自检」看到 PASS。
6. 退出，在 MC Studio 里移除全部组件（含 DebugBridge），重进 → 再按「自检」PASS，即完成零附加包部署。

**使用**：每次换提示词先按「清空」→ 按 1–15 个字 → 按「生成」，生成的字显示在聊天栏。生成和自检都不会清掉已输入的字。
